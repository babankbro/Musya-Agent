### Two-Cache Architecture (สิ่งที่ค้นพบ)

```
Cache Layer 1 (มีอยู่แล้ว): Redis "pdf_cache:<sha256(pdf_url)>"
  ── ของ ThaiJO µservice (:8505)
  ── cache: GPT-4.1 article summary per pdf_url
  ── key คือ sha256(pdf_url) — ไม่สามารถ reverse กลับเป็น URL ได้
  ── Tab 4 "แคช" ใน frontend แสดง Redis entries เหล่านี้
  ── ไม่สามารถตอบ "search term X ได้ pdf_url อะไรบ้าง" ได้โดยตรง

Cache Layer 2 (implement แล้ว ✅): PostgreSQL "thaijo_search_cache"
  ── key: sha256(normalized_term + "|size=N")
  ── value: results_json JSONB = [{pdf_url, reference, summary, search_term, ...}]
  ── ใช้ anchor pdf_url ก่อนส่ง LLM
  ── ใช้ verify citation URL ใน Task 3
  ── คือ source of truth สำหรับ sync evidence_registry (Task 3C)

Tab 4 "แคช" frontend ← GET /api/thaijo/cache (Redis entries)
                       ← GET /api/thaijo/cache/stats
  ── แสดง: key list, preview, size, filter, export, delete
```

**ทำไม Redis cache ใช้ sync ได้แค่อ้อม:** Redis key คือ `sha256(pdf_url)` — ไม่ reversible

## Root Cause Analysis

### RC-1: `pdf_url` ไม่มี anchor — ผ่าน LLM 4 ครั้งโดยไม่มี validation

**Pipeline: `thaijo_research_orchestrator.py`**

```
search_thaijo() → Searcher LLM → Screener LLM → Citation LLM → Report Composer LLM
     (API truth)    [HOP 1]         [HOP 2]         [HOP 3]          [HOP 4]
```

แต่ละ hop: LLM อ่าน JSON context → serialize ใหม่ → URL อาจ truncate/mutate ได้

**Observed mutation patterns:**
| Pattern | ตัวอย่าง | สาเหตุ |
|---------|---------|--------|
| URL truncation | `…/view/12345` → `…/view/123` | LLM ตัดท้ายตัวเลขที่ยาว |
| Path confusion | `…/view/` → `…/download/` | LLM "แก้" path ที่คิดว่าผิด |
| Domain drift | `he01.tci-thaijo.org` → `he02.tci-thaijo.org` | LLM สับสน subdomain |
| Journal slug mutation | `/index.php/foo/` → `/index.php/bar/` | LLM ผสม slug จากหลายบทความ |

**ไฟล์ที่เกี่ยวข้อง:**
- `src/agents/thaijo_searcher.py` — Hop 1
- `src/agents/thaijo_screener.py` — Hop 2 (pure LLM, ไม่มี tool)
- `src/agents/citation_evidence.py` — Hop 3
- `src/agents/thaijo_report_composer.py` — Hop 4

### RC-4: Fuzzy URL recovery ใน `_parse()` ใช้ threshold ต่ำและ source ที่ผิด

**ไฟล์:** `src/agents/thaijo_research_orchestrator.py:95-112`
```python
# Fix hallucinated URLs using fuzzy matching on bibliography/summary
if real_articles:
    for c in citations:
        ...
        ratio = difflib.SequenceMatcher(None, ref1[:150], ref2[:150]).ratio()
        if best_match and best_ratio > 0.3:          # ← threshold ต่ำมาก
            c.open_url = best_match.get("pdf_url", c.open_url)
```

**ปัญหา 3 ข้อ:**
1. **`real_articles` มาจาก Screener output (`to[2]`)** ซึ่งผ่าน LLM แล้ว — ไม่ใช่ API truth
2. **Threshold 0.3 ต่ำเกิน** สำหรับบทความหัวข้อใกล้เคียงกัน (เช่น 3 บทความเรื่องอุบัติเหตุ) → match ผิดบทความ → URL ผิดบทความ
3. **เปรียบเทียบแค่ 150 chars แรก** ซึ่งมักเป็นชื่อผู้แต่งที่คล้ายกัน

**กรณีเลวร้ายที่สุด:** Citation C-203 ได้ URL ของ C-205 เพราะ fuzzy match ผิด → ผู้ใช้คลิกลิงค์ไปบทความคนละเรื่อง

**Helper function:**
```python
def _confirm_thaijo_url(pdf_url: str, search_term: str) -> str:
    """Verify pdf_url against thaijo_search_cache.
    Re-fetches via search_thaijo if not in cache.
    Returns confirmed URL or "" if unverifiable."""
    from src.tools.thaijo import _is_valid_thaijo_url, _search_thaijo_impl

    # Step 1: fast pattern check
    if not _is_valid_thaijo_url(pdf_url):
        return ""

    # Step 2: check PostgreSQL cache (JSONB contains query)
    try:
        from src.db.pool import query_db
        rows = query_db(
            "SELECT 1 FROM thaijo_search_cache "
            "WHERE results_json @> %s::jsonb AND expires_at > NOW() LIMIT 1",
            (json.dumps([{"pdf_url": pdf_url}]),),
        )
        if rows:
            return pdf_url  # confirmed: URL exists in API-sourced cache
    except Exception as e:
        logger.warning("ThaiJO cache lookup failed: %s — fail open", e)
        return pdf_url  # DB error → fail open (keep URL)

    # Step 3: cache MISS — re-search with same term via same API path as Tab 1
    if search_term:
        try:
            raw = _search_thaijo_impl(search_term, size=10, strict=False)
            data = json.loads(raw)
            real_urls = {r.get("pdf_url", "") for r in data.get("results", [])}
            if pdf_url in real_urls:
                return pdf_url  # found in fresh API result → confirmed
            # URL not in API results → hallucinated
            logger.warning(
                "ThaiJO URL not found in re-search for term=%r: %r",
                search_term, pdf_url[:80],
            )
        except Exception as e:
            logger.warning("ThaiJO re-search failed: %s — fail open", e)
            return pdf_url  # fail open

    return ""  # no search_term + not in cache → cannot confirm → clear
```

```python
"""Re-verify ThaiJO evidence_registry entries using direct API search.

Uses same code path as POST /api/thaijo/search (Tab 1) — zero LLM hops.
Run after database migration to clean up historically hallucinated URLs.
"""
import json, logging
from src.db.pool import query_db, execute_db
from src.tools.thaijo import _search_thaijo_impl, _is_valid_thaijo_url

logger = logging.getLogger(__name__)

def run_cleanup():
    # Get all ThaiJO entries with cleared URL + their search term
    rows = query_db(
        """SELECT DISTINCT er.evidence_id, er.source_ref, er.open_url,
                  er.thaijo_search_term, er.thaijo_pdf_url
           FROM evidence_registry er
           WHERE er.evidence_type = 'thaijo_article'
           ORDER BY er.evidence_id""",
        [],
    )
    logger.info("Found %d ThaiJO evidence entries to verify", len(rows))

    cleared = 0
    recovered = 0

    for row in rows:
        ev_id = row["evidence_id"]
        current_url = row.get("open_url", "")
        search_term = row.get("thaijo_search_term", "")
        stored_pdf_url = row.get("thaijo_pdf_url", "")  # from migration 015

        # Case 1: open_url already valid (in pattern) — spot-check against cache
        if current_url and _is_valid_thaijo_url(current_url):
            cache_rows = query_db(
                "SELECT 1 FROM thaijo_search_cache "
                "WHERE results_json @> %s::jsonb AND expires_at > NOW() LIMIT 1",
                (json.dumps([{"pdf_url": current_url}]),),
            )
            if not cache_rows and search_term:
                # Not in cache — re-search to verify
                raw = _search_thaijo_impl(search_term, size=10, strict=False)
                data = json.loads(raw)
                real_urls = {r.get("pdf_url") for r in data.get("results", [])}
                if current_url not in real_urls:
                    execute_db(
                        "UPDATE evidence_registry SET open_url='' WHERE evidence_id=%s",
                        (ev_id,),
                    )
                    logger.warning("Cleared unconfirmed URL for %s: %r", ev_id, current_url[:60])
                    cleared += 1
            continue

        # Case 2: open_url empty or invalid — try to recover using search_term
        if search_term:
            raw = _search_thaijo_impl(search_term, size=10, strict=False)
            data = json.loads(raw)
            real_urls = [r.get("pdf_url") for r in data.get("results", []) if r.get("pdf_url")]

            # Try to match stored_pdf_url (from migration 015) against fresh results
            if stored_pdf_url and stored_pdf_url in real_urls:
                execute_db(
                    "UPDATE evidence_registry SET open_url=%s WHERE evidence_id=%s",
                    (stored_pdf_url, ev_id),
                )
                logger.info("Recovered URL for %s: %r", ev_id, stored_pdf_url[:60])
                recovered += 1
            elif real_urls:
                logger.info("Could not match %s — %d URLs available but none match", ev_id, len(real_urls))

    logger.info("Cleanup complete: %d cleared, %d recovered out of %d entries",
                cleared, recovered, len(rows))

if __name__ == "__main__":
    logging.basicConfig(level=logging.INFO)
    run_cleanup()
```

```python
class SyncEvidenceResult(BaseModel):
    synced: int        # entries ที่ open_url ถูกอัปเดตด้วย confirmed URL
    cleared: int       # entries ที่ open_url ถูก clear (URL ไม่พบในcache)
    unchanged: int     # entries ที่ไม่มีการเปลี่ยนแปลง
    errors: int        # entries ที่เกิด error ระหว่าง sync
    details: list[dict]  # รายการสรุปต่อ entry (สำหรับ debug/display)

@router.post("/sync-evidence", response_model=SyncEvidenceResult)
async def sync_evidence_registry():
    """Sync evidence_registry ThaiJO entries using confirmed URLs from thaijo_search_cache.

    Strategy:
    1. Query evidence_registry WHERE evidence_type='thaijo_article'
    2. For each entry, normalize its thaijo_search_term
    3. JSONB query thaijo_search_cache WHERE normalized_term matches + not expired
    4. Extract pdf_url from results_json that best matches source_ref/thaijo_pdf_url
    5. Update open_url: confirmed URL if match found, "" if clearly wrong, unchanged if no data
    """
    from src.db.pool import query_db, execute_db
    import json, re

    def _normalize(t: str) -> str:
        return re.sub(r'\s+', ' ', (t or "").lower().strip())

    rows = query_db(
        """SELECT evidence_id, source_ref, open_url,
                  thaijo_search_term, thaijo_pdf_url
           FROM evidence_registry
           WHERE evidence_type = 'thaijo_article'
           ORDER BY evidence_id""",
        [],
    )

    synced = cleared = unchanged = errors = 0
    details = []

    for row in rows:
        ev_id = row["evidence_id"]
        current_url = row.get("open_url", "")
        search_term = row.get("thaijo_search_term", "")
        stored_pdf_url = row.get("thaijo_pdf_url", "")

        if not search_term:
            unchanged += 1
            details.append({"id": ev_id, "action": "unchanged", "reason": "no_search_term"})
            continue

        try:
            norm = _normalize(search_term)
            # Find cache entries for this search term (any size)
            cache_rows = query_db(
                """SELECT results_json FROM thaijo_search_cache
                   WHERE normalized_term = %s AND expires_at > NOW()
                   ORDER BY api_called_at DESC LIMIT 1""",
                (norm,),
            )

            if not cache_rows:
                # Try partial match (search term may differ by size param)
                cache_rows = query_db(
                    """SELECT results_json FROM thaijo_search_cache
                       WHERE normalized_term LIKE %s AND expires_at > NOW()
                       ORDER BY hit_count DESC LIMIT 1""",
                    (f"%{norm[:30]}%",),
                )

            if not cache_rows:
                unchanged += 1
                details.append({"id": ev_id, "action": "unchanged", "reason": "no_cache_entry"})
                continue

            articles = cache_rows[0]["results_json"] or []
            cached_urls = [a.get("pdf_url", "") for a in articles if a.get("pdf_url")]

            # Priority 1: current URL is already in cache → confirmed, no change
            if current_url and current_url in cached_urls:
                unchanged += 1
                details.append({"id": ev_id, "action": "unchanged", "reason": "url_confirmed"})
                continue

            # Priority 2: stored thaijo_pdf_url (original from migration 015) in cache → restore
            if stored_pdf_url and stored_pdf_url in cached_urls:
                execute_db(
                    "UPDATE evidence_registry SET open_url=%s WHERE evidence_id=%s",
                    (stored_pdf_url, ev_id),
                )
                synced += 1
                details.append({"id": ev_id, "action": "synced", "url": stored_pdf_url[:60]})
                continue

            # Priority 3: current URL not in cache + pattern invalid → clear
            if current_url:
                from src.tools.thaijo import _is_valid_thaijo_url
                if not _is_valid_thaijo_url(current_url):
                    execute_db(
                        "UPDATE evidence_registry SET open_url='' WHERE evidence_id=%s",
                        (ev_id,),
                    )
                    cleared += 1
                    details.append({"id": ev_id, "action": "cleared", "reason": "invalid_pattern"})
                    continue

            # Priority 4: open_url valid pattern but not in cache → clear (likely hallucinated)
            if current_url and cached_urls:
                execute_db(
                    "UPDATE evidence_registry SET open_url='' WHERE evidence_id=%s",
                    (ev_id,),
                )
                cleared += 1
                details.append({"id": ev_id, "action": "cleared", "reason": "not_in_cache"})
                continue

            unchanged += 1
            details.append({"id": ev_id, "action": "unchanged", "reason": "no_match"})

        except Exception as e:
            logger.error("sync_evidence: error for evidence_id=%s: %s", ev_id, e)
            errors += 1
            details.append({"id": ev_id, "action": "error", "reason": str(e)[:60]})

    logger.info(
        "sync-evidence complete: synced=%d cleared=%d unchanged=%d errors=%d",
        synced, cleared, unchanged, errors,
    )
    return SyncEvidenceResult(
        synced=synced, cleared=cleared, unchanged=unchanged,
        errors=errors, details=details,
    )
```

#### Task 4: แทน fuzzy matching ด้วย cache lookup ใน `_parse()`

**Root cause addressed:** RC-4

**Description:**
`_parse()` ใน `thaijo_research_orchestrator.py` มี fuzzy URL recovery ที่ใช้ Screener output
และ `difflib.SequenceMatcher` threshold 0.3

แทนด้วย: lookup URL จาก **Searcher output (`to[1]`)** ซึ่งใกล้ API มากกว่า
สร้าง `pdf_url → article` map จาก Searcher output ก่อน
ใช้ exact match (หรือ prefix match สำหรับ truncation recovery) แทน fuzzy

**ลำดับ URL correction ใน `_parse()`:**
```
Priority 1: exact match url in searcher_articles map
Priority 2: cache lookup _verify_thaijo_url_in_cache(url)
Priority 3: bibliography_text → SequenceMatcher กับ searcher articles (ไม่ใช่ screener)
            threshold เพิ่มเป็น 0.6 (จาก 0.3)
Priority 4: ถ้า ratio < 0.6 → clear open_url = ""
```

**Code change:**
```python

searcher_articles = []
if to and len(to) >= 2:
    try:
        searcher_raw = getattr(to[1], "raw", "") or str(to[1])
        s, e = searcher_raw.find("{"), searcher_raw.rfind("}")
        if s != -1 and e > s:
            searcher_data = json.loads(searcher_raw[s:e+1])
            searcher_articles = searcher_data.get("articles", [])
    except Exception:
        pass

searcher_url_map = {art.get("pdf_url", ""): art for art in searcher_articles if art.get("pdf_url")}

# URL correction loop
for c in citations:
    if c.open_url and c.open_url in searcher_url_map:
        # Priority 1: exact match — already correct, reinforce with searcher data
        art = searcher_url_map[c.open_url]
        if art.get("reference"):
            c.bibliography_text = art["reference"]
        continue

    # Priority 2: pattern check + cache lookup
    if c.open_url and not _is_valid_thaijo_pattern(c.open_url):
        c.open_url = ""
        continue

    # Priority 3: fuzzy match on searcher articles (not screener), threshold 0.6
    if searcher_articles:
        best_match, best_ratio = None, 0.0
        for art in searcher_articles:
            ref2 = art.get("reference") or art.get("summary", "")
            ratio = difflib.SequenceMatcher(None, (c.bibliography_text or "")[:200], ref2[:200]).ratio()
            if ratio > best_ratio:
                best_ratio, best_match = ratio, art
        if best_match and best_ratio >= 0.6:   # เพิ่มจาก 0.3 → 0.6
            c.open_url = best_match.get("pdf_url", c.open_url)
            if best_match.get("reference"):
                c.bibliography_text = best_match["reference"]
        elif best_ratio < 0.6:
            c.open_url = ""  # ไม่พบ match ที่น่าเชื่อถือ → clear
```

## Risk Register

| Risk | Impact | Mitigation |
|------|--------|------------|
| GIN index JSONB ทำ write ช้า | Low | Benchmark ก่อน deploy; < 10k rows ปกติเพียงพอ |
| `_confirm_thaijo_url()` re-search เพิ่ม latency ใน register_evidence | Medium — ต่อ ThaiJO item | Cache HIT path: DB query เดียว (~1ms); re-search เฉพาะ MISS; timeout 20s ถูก inherit |
| Cleanup script ลบ URL ที่จริงแล้วถูกต้อง (false negative) | Low — recoverable | Script log ทุก action; `thaijo_pdf_url` column (migration 015) เก็บ URL ต้นฉบับไว้ recover |
| `_search_thaijo_impl()` timeout ใน cleanup | Low — 120s timeout | Script ใช้ strict=False + size=10; skip term ที่ fail |
| Fuzzy threshold 0.6 สูงเกิน → clear URL จริง | Low | Monitor cleared count in logs; ปรับ threshold ได้ |
| Cache TTL 7 วัน + journal เพิ่ม paper ใหม่ | Low | `DELETE FROM thaijo_search_cache WHERE search_term='...'` |
| `fail open` ขณะ DB down ใน `_confirm_thaijo_url()` | Medium — URL อาจหลุดผ่าน | Tradeoff: ดีกว่า false-clear URL ที่ถูกต้อง |
| sync-evidence: `normalized_term` partial match ผิด entry | Low | query exact match ก่อน, fallback LIKE เฉพาะเมื่อ exact ไม่พบ |
| sync-evidence เรียกขณะ cache expired ทั้งหมด | Medium | ถ้า cache ว่าง → unchanged สำหรับทุก entry; ผู้ใช้ต้องรอ cache refresh |
| sync-evidence กดซ้ำโดยบังเอิญ | Low | endpoint idempotent: confirmed entries → unchanged (ไม่ update ซ้ำ) |

## Open Questions (ลำดับความสำคัญ)

1. **[HIGH] JSONB `@>` query ทำงานได้กับ partial object ไหม?**
   Query: `results_json @> '[{"pdf_url": "https://..."}]'::jsonb`
   ต้องทดสอบกับ PostgreSQL จริงก่อน implement Task 3 — ถ้าไม่ work ให้เปลี่ยนเป็น `results_json::text LIKE '%url%'`

2. **[MEDIUM] Cache key รวม `size` parameter ไหม?**
   `search_thaijo("อุบัติเหตุ", size=5)` กับ `size=10` → same cache key หรือไม่?
   Recommendation: normalize key รวม size ด้วย → `sha256(f"{normalized_term}|size={size}")`
   เพื่อป้องกัน returning 5 results เมื่อ caller ขอ 10

3. **[LOW] `fail open` policy สำหรับ `_verify_thaijo_url_in_cache()` เมื่อ DB down**
   ปัจจุบัน: return `True` (keep URL) เมื่อ DB error
   Alternative: return `False` (clear URL) เพื่อ safety
   ต้องตัดสินใจก่อน Task 3

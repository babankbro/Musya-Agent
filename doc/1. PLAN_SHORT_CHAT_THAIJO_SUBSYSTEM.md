## 2. Short Chat Branch

### 2.1 วัตถุประสงค์

ปัจจุบัน Chat Pipeline ใช้ 9 agents ใช้เวลา 3–5 นาที ซึ่งนานเกินไปสำหรับคำถามง่าย ๆ
Short Chat ให้ผลลัพธ์ภายใน **30–60 วินาที** โดยข้ามขั้นตอนที่ไม่จำเป็น

### 2.2 สถาปัตยกรรม

```
User Message (mode=short_chat)
    │
    ▼
┌──────────────────────────────────────┐
│        REQUEST ROUTER AGENT          │
│  → ตรวจจับ mode flag หรือ query สั้น │
│  → Output: pipeline = "short_chat"   │
└─────────────────┬────────────────────┘
                  │
                  ▼
┌──────────────────────────────────────┐
│         SHORT CHAT PIPELINE          │
│                                      │
│  SC-1. Request Interpreter           │
│        (shared with foundation)      │
│                                      │
│  SC-2. Quick Retrieval               │
│        - search_documents (1 round)  │
│        - get_accident_summary (ถ้าถาม)│
│        - search_thaijo (optional)    │
│        ไม่ใช้ SQL Specialist         │
│                                      │
│  SC-3. Quick Answer Writer           │
│        - สรุป 500–1,000 คำ           │
│        - Markdown ง่าย               │
│        - APA citations (ไม่เต็มรูป)  │
│                                      │
└─────────────────┬────────────────────┘
                  │
                  ▼
         ShortChatResponse
         { content, citations[], elapsed }
```

### 2.3 เปรียบเทียบ Pipeline

| ด้าน | Full Chat Pipeline | Short Chat Pipeline |
|------|-------------------|---------------------|
| จำนวน agents | 9 | 3 |
| เวลาโดยประมาณ | 3–5 นาที | 30–60 วินาที |
| กราฟ | ✅ | ❌ |
| SQL วิเคราะห์ | ✅ | ❌ |
| Research Synthesizer | ✅ | ❌ |
| Deep Analyst | ✅ | ❌ |
| ความยาวรายงาน | 2,000–4,000 คำ | 500–1,000 คำ |
| Citation | APA เต็มรูป | สรุปอ้างอิง |
| ThaiJO | ✅ | ✅ (optional) |

### 2.4 Agent ใหม่ที่ต้องสร้าง

#### SC-3: Quick Answer Writer (`src/agents/quick_answer_writer.py`)

```python

# Output: Markdown พร้อม inline citation [C-xxx]
# Tools: ไม่มี (ใช้ output จาก SC-1 และ SC-2)
```

#### SC Orchestrator (`src/agents/short_chat_orchestrator.py`)

```python

        crew   = Crew(agents=[...], tasks=[...], process=Process.sequential)
        result = crew.kickoff()
        return ShortChatResponse(...)
```

### 2.5 API Endpoint ใหม่

```
POST /api/chat/short
{
    "message": "จุดเสี่ยงอุบัติเหตุอุบลราชธานี",
    "session_id": null
}
```

**Response:**
```json
{
    "pipeline_used": "short_chat",
    "content": "## สรุปจุดเสี่ยง\n...",
    "citations": [
        { "code": "C-101", "bibliography_text": "...", "open_url": "..." }
    ],
    "elapsed_seconds": 45.2
}
```

**SSE Streaming:** `POST /api/chat/short/stream`
- Events: `start`, `agent_progress` (3 events), `content`, `done`

### 2.6 การ Routing

Router อัปเดตให้รองรับ 3 pipelines:

| เงื่อนไข | Pipeline |
|-----------|----------|
| mode flag = "short" (จาก UI) | `short_chat` |
| คำถาม ≤ 15 คำ + ไม่ขอรายงาน | `short_chat` (optional auto-detect) |
| คำถามสถิติ/กราฟ/วิเคราะห์ | `chat_pipeline` |
| ขอ Policy Brief/รายงานนโยบาย | `policy_brief_pipeline` |

> **หมายเหตุ**: auto-detect เป็น optional feature ระยะแรกให้ user เลือก mode ผ่าน UI

### 2.7 Schema ใหม่

`src/schemas/short_chat.py`:
```python
class ShortChatRequest(BaseModel):
    message: str
    session_id: str | None = None

class ShortChatResponse(BaseModel):
    pipeline_used: str = "short_chat"
    content: str
    citations: list[dict] = []
    elapsed_seconds: float
    follow_up_questions: list[str] = []
```

## 3. ThaiJO Subsystem ใน Shared Foundation

### 3.1 สถานะปัจจุบัน

ThaiJO มีอยู่แล้วใน:
- `tools/thaijo.py` — `search_thaijo` tool
- `src/agents/retrieval.py` — tool ที่ 11 (ใน Retrieval Agent)
- `database/015_thaijo_evidence.sql` — thaijo_* columns ใน evidence_registry
- Citation range: C-200~C-299

**ปัญหา**: ThaiJO ยังถูกเรียกใช้แบบ opt-in ไม่มีการ configure อย่างเป็นทางการ
และยังไม่ถูก document ว่าเป็น "subsystem" ของ Shared Foundation

### 3.2 สถาปัตยกรรม ThaiJO Subsystem

```
┌────────────────────────────────────────────────────────────┐
│              SHARED FOUNDATION (Agents 1-4)                │
│                                                            │
│  ┌─────────────────────────────────────────────────────┐  │
│  │              ThaiJO Academic Subsystem              │  │
│  │                                                     │  │
│  │  Tool: search_thaijo(query, max_results=5)          │  │
│  │  Source: api.thaijo.org (port 8505 microservice)    │  │
│  │  Citations: C-200~C-299                             │  │
│  │  Trust Level: medium                                │  │
│  │  Evidence Type: thaijo_article                      │  │
│  │                                                     │  │
│  │  เปิดใช้งานใน:                                      │  │
│  │  ✅ Chat Pipeline (Agent 2 — tool 11)               │  │
│  │  ✅ Short Chat Pipeline (SC-2 — optional)           │  │
│  │  ✅ Policy Brief Pipeline (Agent 2 — tool 11)       │  │
│  └─────────────────────────────────────────────────────┘  │
│                                                            │
│  1. Request Interpreter                                    │
│  2. Data Retrieval (+ ThaiJO tool)  ←── ThaiJO บูรณาการ   │
│  3. SQL Specialist                                         │
│  4. Citation & Evidence (+ thaijo_article APA)            │
└────────────────────────────────────────────────────────────┘
```

### 3.3 การเปลี่ยนแปลงใน Code

#### `src/agents/shared_foundation.py`

เพิ่ม `include_thaijo` parameter (default=True เพราะ ThaiJO เปิดอยู่แล้ว):

```python
def build_foundation_agents(
    llm,
    include_nlm: bool = False,
    include_thaijo: bool = True,   # ← ใหม่ (เปิดเป็น default)
    province: str = None,
    notebook_id: str = None,
    mode: str = 'full'             # ← ใหม่: 'full' | 'short'
) -> dict:
    ...
    retrieval_tools = STANDARD_TOOLS.copy()
    if include_thaijo:
        retrieval_tools.append(search_thaijo)   # tool 11
    if include_nlm:
        retrieval_tools += [nlm_ask, get_supported_provinces]
```

#### `src/agents/citation_evidence.py`

เพิ่ม logic สำหรับ `thaijo_article` APA format:
- apa_type: `"article"`
- ใช้ `bibliography_text` format: `{author}. ({year}). {title}. *{journal}*, *{volume}*({issue}), {pages}. {doi}`
- open_url: ลิงก์ไปยัง thaijo.org article

### 3.4 ThaiJO Context Context ที่ให้กับ Pipeline

ThaiJO ให้ **academic context** ที่ขาดหายไปจากฐานข้อมูล:
- งานวิจัยระดับชาติที่เกี่ยวกับสาธารณสุขไทย
- บทความวิชาการเกี่ยวกับอุบัติเหตุ สุขภาพจิต NCD
- อ้างอิงที่ผ่าน peer-review (น่าเชื่อถือกว่า website ทั่วไป)

## 4. UI Mode Toggle

### 4.1 การออกแบบ Toggle

Toggle อยู่ใน **Chat tab** — ในพื้นที่ input ด้านบน textarea:

```
┌─────────────────────────────────────────────────────┐
│  [📊 รายงานเต็ม]  [💬 ถามสั้น]                      │
│                                                     │
│  ┌───────────────────────────────────────────────┐  │
│  │ ถามเกี่ยวกับข้อมูลอุบัติเหตุ...               │  │
│  └───────────────────────────────────────────────┘  │
│  Enter ส่ง · Shift+Enter ขึ้นบรรทัดใหม่  [ล้างแชท] │
└─────────────────────────────────────────────────────┘
```

**Behavior:**
- เลือก "รายงานเต็ม" → ใช้ `/api/chat/stream` (SSE, multi-agent, รายงาน 2,000+ คำ)
- เลือก "ถามสั้น" → ใช้ `/api/chat/short/stream` (SSE, 3 agents, 500–1,000 คำ)

**Visual indicators:**
- รายงานเต็ม: teal toggle active + placeholder "ขอรายงาน Policy Brief หรือสถิติเชิงลึก..."
- ถามสั้น: amber/orange toggle active + placeholder "ถามคำถามสั้น เช่น 'จุดเสี่ยงอุบลฯ มีที่ไหนบ้าง'"

### 4.2 Quick Prompts เปลี่ยนตาม Mode

**รายงานเต็ม** (quick prompts ปัจจุบัน):
- สถิติอุบัติเหตุ อุบลฯ 2024
- Policy Brief อุบลฯ (RTI+MH+NCD)
- ตรวจราชการ ศรีสะเกษ

**ถามสั้น** (quick prompts ใหม่):
- จุดเสี่ยงสูงสุดอุบลฯ?
- อุบัติเหตุปี 2024 ลดหรือเพิ่ม?
- จังหวัดไหนในเขต 10 อุบัติเหตุมากสุด?
- NCD ในมุกดาหารเป็นอย่างไร?

### 4.3 ผลลัพธ์ต่างกัน

**รายงานเต็ม** — แสดงผลเหมือนเดิม:
- Markdown bubble + กราฟ + citations + follow-up questions
- Agent timeline ขณะรอ

**ถามสั้น** — แสดงผลแบบ compact:
- Text bubble เรียบง่าย
- Mini-citations ท้าย bubble (ไม่ต้องขยาย)
- ไม่มีกราฟ
- Loading แบบ 3 dots ไม่มี timeline

## 6. ข้อควรระวัง

| ประเด็น | รายละเอียด | วิธีแก้ |
|---------|-----------|--------|
| **Short Chat ไม่มี SQL** | ข้อมูลเชิงลึกจาก SQL จะขาด | บอก user ใน response ว่าใช้ "รายงานเต็ม" สำหรับกราฟ |
| **ThaiJO API latency** | search_thaijo อาจช้าถ้า microservice ไม่ up | ใส่ timeout 10s + fallback gracefully |
| **Short chat citation ไม่สมบูรณ์** | ไม่ได้ผ่าน Citation & Evidence Agent เต็ม | ใส่ disclaimer: "อ้างอิงเบื้องต้น ยังไม่ผ่านการตรวจสอบ APA เต็มรูป" |
| **Router ต้องรับ mode flag** | mode ส่งมาจาก UI ไม่ใช่จาก LLM วิเคราะห์ | เพิ่ม `mode` field ใน ChatRequest schema |
| **evidence_type constraint** | migration 010 ยังไม่รองรับ thaijo_article | รัน SQL fix ก่อน: `ALTER TABLE evidence_registry DROP CONSTRAINT evidence_type_check; ALTER TABLE ... ADD CONSTRAINT ...` (ดู DATABASE_API_ARCHITECTURE.md) |

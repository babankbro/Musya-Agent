# 02.07 - Agent: Accident Policy — เขตสุขภาพที่ 10

> **Standalone 3-agent pipeline** สำหรับผลิตรายงานนโยบายอุบัติเหตุทางถนน เขตสุขภาพที่ 10  
> (อุบลราชธานี · ศรีสะเกษ · ยโสธร · อำนาจเจริญ · มุกดาหาร)  
> ตอบ 7 คำถามนโยบาย ใน 4 หมวด ด้วย Haddon Matrix framework  
> ออกรายงานสำหรับ สสส. / สสจ. / ศปถ.

## 2. Agent 1 — Zone10SqlFetcher

**File**: `src/agents/accident_policy_agent.py` → `create_zone10_sql_fetcher()`  
**File**: `src/tools/zone10_accident.py` (tools)

### 2.1 Agent Profile

```
Role      : Zone 10 SQL Data Fetcher
Goal      : ดึงข้อมูลอุบัติเหตุทางถนนในเขตสุขภาพที่ 10
            โดยเรียกเครื่องมือทั้ง 7 ตัวและรวบรวมผลลัพธ์ครบถ้วน
Backstory : ผู้เชี่ยวชาญด้านฐานข้อมูลอุบัติเหตุ PostgreSQL star-schema
            รายงานตามที่ข้อมูลระบุ ไม่ตีความหรือสรุปเอง

Tools     : 7 (ดูหัวข้อ 4)
```

### 2.2 Task Description

```
Task A — Fetch
──────────────
Input  : provinces (comma-separated), year_range
Actions: เรียก 7 tools ตามลำดับ Q1→Q7 ส่ง provinces parameter ให้แต่ละ tool
Output : ผลลัพธ์รวม Q1: ... Q2: ... ถึง Q7: ... ไม่ตัดทอน
```

### 2.3 Data Flow — Tool invocation

```
SqlFetcher receives task
    │
    ├── get_zone10_top_roads(provinces, top_n=10)
    │       └── _query_top_roads() → mart_province_road
    │
    ├── get_zone10_time_bands(provinces)
    │       └── _query_time_bands() → fact_accident_event + dim_geography
    │
    ├── get_zone10_motorcycle_severity(provinces)
    │       └── _query_motorcycle_severity() → fact_accident_event + dim_geography
    │              WHERE vehicle_type ILIKE %s ('จักรยานยนต์')
    │
    ├── get_zone10_car_serious_injuries(provinces)
    │       └── _query_car_serious_injuries() → fact_accident_event + dim_geography
    │              WHERE vehicle_type NOT ILIKE %s ('จักรยาน')
    │
    ├── get_zone10_environment_risk(provinces)
    │       └── _query_environment_risk() → fact_accident_event + dim_geography
    │
    ├── get_zone10_yearly_kpi(provinces)
    │       └── _query_yearly_kpi() → mart_province_year
    │
    └── get_zone10_monthly_risk(provinces)
            └── _query_monthly_risk() → mart_accident_summary
```

### 3.2 Haddon Matrix Framework

Analyst ใช้ Haddon Matrix จัดความสัมพันธ์ระหว่างข้อมูลกับมาตรการนโยบาย:

```
                ┌───────────────┬──────────────────┬──────────────────┐
                │  ก่อนเกิดเหตุ │  ขณะเกิดเหตุ    │  หลังเกิดเหตุ   │
┌───────────────┼───────────────┼──────────────────┼──────────────────┤
│ คน (Human)   │ Q3/Q4         │ Q3/Q4            │ EMS response     │
│               │ พฤติกรรมเสี่ยง│ ความรุนแรง       │ (implicit)       │
├───────────────┼───────────────┼──────────────────┼──────────────────┤
│ รถ/ถนน       │ Q1            │ Q5               │ Q2               │
│ (Vehicle/Road)│ จุดเสี่ยง Black│ สภาพแวดล้อม     │ เวลา EMS         │
│               │ Spot          │                  │ scheduling       │
├───────────────┼───────────────┼──────────────────┼──────────────────┤
│ ระบบ (System) │ Q6            │ Q7               │ Q6               │
│               │ แนวโน้ม KPI   │ เทศกาลเสี่ยง     │ เป้าหมายลดตาย   │
```

### 4.2 Report Structure (5 Sections)

```
รายงานตรวจราชการและนิเทศงาน กรณีปกติ ระดับกระทรวงสาธารณสุข
เขตสุขภาพที่ 10 — อุบัติเหตุทางถนน

ส่วนที่ 1 — สถานการณ์อุบัติเหตุทางถนน เขตสุขภาพที่ 10
    ├── ภาพรวมจำนวนอุบัติเหตุ / เสียชีวิต / บาดเจ็บสาหัส
    └── แนวโน้มรายปี (ตาราง)

ส่วนที่ 2 — จุดเสี่ยง (Black Spot) และช่วงเวลาอันตราย
    ├── Top 10 ถนนเสี่ยง (hotspot_score + dominant_cause)
    └── ช่วงเวลาเสี่ยงสูงสุด → EMS scheduling

ส่วนที่ 3 — ปัจจัยพฤติกรรมและสภาพแวดล้อม
    ├── อุบัติเหตุจักรยานยนต์: ความรุนแรงแยกระดับ
    ├── สภาพแสง/ถนนที่สัมพันธ์กับอุบัติเหตุรุนแรง
    └── ⚠️ ข้อจำกัดข้อมูล (ไม่มี helmet/seatbelt ระดับบุคคล)

ส่วนที่ 4 — ผลการดำเนินงานตามตัวชี้วัด (KPI)
    ├── ตาราง: ตัวชี้วัด | เป้าหมาย | ผลงาน | สถานะ
    └── เป้าหมายลดผู้เสียชีวิต ≥5% YoY

ส่วนที่ 5 — ข้อเสนอแนะเชิงนโยบาย
    ├── ระยะสั้น  (0-6 เดือน)  — ผู้รับผิดชอบ / KPI
    ├── ระยะกลาง (6-12 เดือน) — ผู้รับผิดชอบ / KPI
    └── ระยะยาว  (1-3 ปี)     — ผู้รับผิดชอบ / KPI
```

| Rule | Detail |
|------|--------|
| ภาษา | ทางการ เหมาะสำหรับเอกสารราชการ |

## 5. SQL Tools — ทั้ง 7 ตัว

**File**: `src/tools/zone10_accident.py`

### 5.1 Helper — `_province_clause()`

สร้าง WHERE fragment สำหรับกรองจังหวัด (ILIKE ทุก province):

```python
def _province_clause(alias: str, provinces: str) -> tuple[str, list]:
    names = [p.strip() for p in provinces.split(",") if p.strip()] or ZONE10_PROVINCES
    col = f"{alias}.province_name" if alias else "province_name"
    parts = " OR ".join([f"{col} ILIKE %s"] * len(names))
    return f"({parts})", [f"%{n}%" for n in names]

# Example output:
# clause  = "(province_name ILIKE %s OR province_name ILIKE %s)"
# params  = ["%ยโสธร%", "%มุกดาหาร%"]
```

> **⚠️ Design Note**: ใช้ parameterized `ILIKE %s` + params แทนการ embed `'%text%'` ตรงใน SQL  
> เพราะ psycopg2 ตีความ literal `%` ใน SQL string เป็น format specifier → `tuple index out of range`

### 5.2 Tool Map

| Tool | Question | Table | Key Fields |
|------|----------|-------|-----------|
| `get_zone10_top_roads` | Q1 — ถนนเสี่ยง Top 10 | `mart_province_road` | hotspot_score, dominant_cause, road_name |
| `get_zone10_time_bands` | Q2 — ช่วงเวลาเสี่ยง | `fact_accident_event` + `dim_geography` | EXTRACT(HOUR), severity_level |
| `get_zone10_motorcycle_severity` | Q3 — จักรยานยนต์แยกความรุนแรง | `fact_accident_event` + `dim_geography` | vehicle_type ILIKE '%จักรยานยนต์%', death_count, serious_injured |
| `get_zone10_car_serious_injuries` | Q4 — รถยนต์/บาดเจ็บสาหัส | `fact_accident_event` + `dim_geography` | vehicle_type NOT ILIKE '%จักรยาน%', serious_injured |
| `get_zone10_environment_risk` | Q5 — สภาพแสง/ถนน กับความรุนแรง | `fact_accident_event` + `dim_geography` | light_condition, road_condition, severity_level |
| `get_zone10_yearly_kpi` | Q6 — แนวโน้ม YoY | `mart_province_year` | year_no, death_count, serious_injured |
| `get_zone10_monthly_risk` | Q7 — ความเสี่ยงรายเดือน/เทศกาล | `mart_accident_summary` | month_no, accident_count, high_risk_timeband |

### 5.3 Tool Architecture Pattern

แต่ละ tool แยกเป็น 2 ชั้น เพื่อให้ test ได้โดยไม่ผ่าน CrewAI wrapper:

```python
# Private logic function — testable directly
def _query_top_roads(provinces: str, top_n: int = 10) -> str:
    clause, params = _province_clause("", provinces)
    sql = f"SELECT ... FROM mart_province_road WHERE {clause} LIMIT %s"
    rows = query_db(sql, tuple(params + [top_n]))
    return format_result(rows)

# Public @tool wrapper — used by Agent
@tool("get_zone10_top_roads")
def get_zone10_top_roads(provinces: str = "", top_n: int = 10) -> str:
    """Q1 (Hotspot): Top accident-prone roads in Zone 10 ranked by hotspot_score."""
    return _query_top_roads(provinces, top_n)
```

> **⚠️ Testing Note**: เรียก `tool.run({"provinces": ...})` ผ่าน CrewAI wrapper ส่ง dict เป็น positional arg  
> ทำให้ได้ `AttributeError: 'dict' object has no attribute 'split'`  
> Tests ต้องเรียก `_query_*()` โดยตรงเสมอ

### 5.4 Data Limitation — Q3 / Q4

```
⚠️ fact_accident_person ไม่มีข้อมูล
   (CSV แหล่งข้อมูลไม่มีข้อมูลระดับบุคคล — helmet, seatbelt, age, sex)

แก้ปัญหา:
   Q3 (Motorcycle severity)  → proxy: fact_accident_event + vehicle_type ILIKE '%จักรยานยนต์%'
   Q4 (Car serious injuries) → proxy: fact_accident_event + vehicle_type NOT ILIKE '%จักรยาน%'

ทุก output ของ Q3/Q4 มี disclaimer: _PERSON_DATA_NOTE
```

## 11. Key Design Decisions

| Decision | Rationale |
|----------|-----------|
| **Standalone pipeline** (not extending Chat/PolicyBrief) | Policy report สำหรับ สสส./สสจ./ศปถ. มีโครงสร้างเฉพาะ 5 ส่วน + KPI table แตกต่างจาก Chat response จึงไม่ reuse orchestrator เดิม |
| **Fast path** `run_zone10_data_only()` | ให้ UI preview ข้อมูลก่อนรัน LLM — ลด cost และเวลารอ |
| **Proxy queries สำหรับ Q3/Q4** | `fact_accident_person` ว่างเปล่าเพราะ CSV แหล่งนี้ไม่มีข้อมูลระดับบุคคล — ใช้ `vehicle_type` filter ใน `fact_accident_event` แทน พร้อมระบุ disclaimer ชัดเจน |
| **`_province_clause()` helper** | สร้าง parameterized ILIKE chain ป้องกัน psycopg2 ตีความ literal `%` ใน SQL เป็น format spec |
| **`_query_*` private functions** | แยก SQL logic ออกจาก `@tool` wrapper เพื่อให้ test โดยตรง ไม่ต้องผ่าน CrewAI Tool |
| **sequential Process** | Agent 2 ต้องได้ raw Q1–Q7 ครบก่อนวิเคราะห์ / Agent 3 ต้องได้ JSON ครบก่อนเขียนรายงาน |
| **Gemini fast vs pro** | SqlFetcher ใช้ flash (เร็ว/ถูก) — เพียงแค่เรียก tools ไม่ต้องใช้ reasoning ลึก; Analyst + Writer ใช้ pro — ต้องการ reasoning และ Thai writing quality |

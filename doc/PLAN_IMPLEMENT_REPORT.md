# Plan: Improve Report Quality — Longer, More Detailed Reports

## Context

Reports generated by the chat pipeline are too short and lack depth. The user wants comprehensive, government-quality Thai health reports with much more text and detail.

**Root causes identified:**
1. **Report Writer prompt is only 31 lines** with "3-5 sentences" for Executive Summary and no word count targets (vs. policy writer at 235 lines)
2. **Analyst outputs structured JSON bullets**, not narrative prose — Report Writer must reconstruct detail from sparse data
3. **Data flow gap**: Report Writer context at `orchestrator.py:146` is `[analyze_task, chart_build_task, citation_task]` — missing `retrieve_task` and `sql_task` raw data
4. **LLM model** `gemini-2.0-flash` optimized for speed, not quality/length. No `max_tokens` or `temperature` configured
5. **Style Guide not enforced** — `doc/REPORT_WRITING_STYLE_GUIDE.md` defines 4-part structure but prompts ignore it
6. **No web research capability** — reports limited to local DB data only

## Implementation Plan (4 Phases)

---

### Phase 1: Fix Data Flow + Enhanced Prompts (Highest Impact, Lowest Risk)

These two changes alone should produce reports 3-5x longer.

#### 1A. Fix data flow — pass raw data to Report Writer

**File:** `src/agents/orchestrator.py`
- **Line 146** — Change `context=[analyze_task, chart_build_task, citation_task]` to include `retrieve_task` and `sql_task`
- **Line 395** — Same change in `run_chat_with_progress()`
- This ensures the Report Writer sees ALL retrieved data, not just the analyst's sparse summary

#### 1B. Rewrite Report Writer prompt (31 lines → ~150 lines)

**File:** `src/agents/report_writer.py`
- Replace `REPORT_WRITER_PROMPT` with a comprehensive prompt modeled after `policy_report_writer.py` (235 lines)
- Add explicit word count targets: "สรุปสาระสำคัญ (400-600 คำ)", each major section "300-500 คำ", total report "2,000-4,000 คำ"
- Enforce the 4-part structure from Style Guide: Situation → Measures → Performance → GAP
- Add Markdown template examples for each section (like policy writer does)
- Add prose instructions: "เขียนเป็นย่อหน้าที่ต่อเนื่อง ไม่ใช่แค่ bullet points"
- Add data presentation rules: rate-per-100k, Median baseline, ✓/✗ status tables
- Update `create_report_writer()` backstory to reference the Style Guide framework and set `max_iter=10`

#### 1C. Expand Analyst prompt for richer output

**File:** `src/agents/analyst_accident.py`
- Expand `ACCIDENT_ANALYSIS_PROMPT` to require 2-3 sentences of narrative context per finding (not just terse labels)
- Add instructions for year-over-year comparisons, regional context, and root cause discussion
- Add instruction to produce prose that the Report Writer can directly weave into narrative sections

### Phase 2: LLM Model Upgrade — Tiered Approach

Use a more capable model for quality-critical agents while keeping Flash for simple tasks.

#### 2A. Add tiered model configuration

**File:** `src/config.py`
- Add `GEMINI_MODEL_PRO: str = "gemini-2.5-pro"` for quality-critical agents
- Keep existing `GEMINI_MODEL` as the fast/default model
- Add `REPORT_MAX_TOKENS: int = 8192` setting

**File:** `.env.example`
- Add `GEMINI_MODEL_PRO=gemini-2.5-pro` and `REPORT_MAX_TOKENS=8192`

#### 2B. Create tiered LLM factory

**File:** `src/agents/orchestrator.py`
- Replace `_get_llm()` string return with CrewAI `LLM` objects:
  - `_get_llm("fast")` → `LLM(model="gemini/gemini-2.0-flash", temperature=0.2, max_tokens=4096)`
  - `_get_llm("pro")` → `LLM(model="gemini/gemini-2.5-pro", temperature=0.3, max_tokens=8192)`
- In `build_crew()`: use "fast" for foundation agents (interpreter, retriever, sql, citation), "pro" for analyst + chart builder + writer

**File:** `src/agents/shared_foundation.py`
- Update `build_foundation_agents()` to accept optional `llm_pro` parameter for future flexibility

**File:** `src/agents/policy_orchestrator.py`
- Apply same tiered approach

### Phase 3: Multi-Agent Report Pipeline (Split Writer into 3 Agents)

Replace the single Report Writer with a 3-stage sub-pipeline for deeper content.

#### 3A. Create Research Synthesizer agent

**New file:** `src/agents/research_synthesizer.py`
- Takes raw data + analyst output → produces detailed narrative prose for each section
- Expands data tables into flowing paragraphs with context, comparisons, and implications
- Uses "pro" LLM tier
- Output: per-section narrative blocks (300-500 words each)

#### 3B. Create Deep Analyst agent

**New file:** `src/agents/deep_analyst.py`
- Provides deeper analysis: root cause analysis (Haddon Matrix), policy implications, cross-regional comparisons, trend projections
- Adds comparative context (national averages, neighboring provinces)
- Uses "pro" LLM tier
- Output: root_cause_analysis, comparative_findings, policy_implications, projected_trends

#### 3C. Rename Report Writer → Report Composer

**File:** `src/agents/report_writer.py` (modify existing)
- Rename to Report Composer role
- Takes Research Synthesizer + Deep Analyst + Charts + Citations → weaves into cohesive final report
- Focuses on narrative flow, transitions, cross-references, and consistency
- Uses "pro" LLM tier

#### 3D. Update orchestrator task chain

**File:** `src/agents/orchestrator.py`
- Change from 7 agents to 9 agents:
  ```
  1. Interpreter → 2. Retrieval → 3. SQL → 4. Citation → 5. Analyst →
  6. Chart Builder → 7. Research Synthesizer (NEW) → 8. Deep Analyst (NEW) → 9. Report Composer (modified)
  ```
- Research Synthesizer context: `[retrieve_task, sql_task, analyze_task, citation_task]`
- Deep Analyst context: `[retrieve_task, sql_task, analyze_task, citation_task]`
- Report Composer context: `[research_synth_task, deep_analyst_task, chart_build_task, citation_task]`
- Update `CHAT_AGENT_NAMES` and agent count in metadata

#### 3E. Update progress tracking

**File:** `src/agents/progress.py`
- Add Research Synthesizer and Deep Analyst to `CHAT_PIPELINE_AGENTS`
- Update order numbers

### Phase 4: Web Research Integration (Optional Enrichment)

Add internet research capability for real-world context.

#### 4A. Create web search tool

**New file:** `src/tools/web_search.py`
- CrewAI `@tool` using Tavily or SerperDev API
- Thai language search with optional `.go.th` domain filter
- Returns structured results: title, snippet, URL, date
- Limit to 5-10 results per query

#### 4B. Add configuration

**File:** `src/config.py`
- Add `SERPER_API_KEY: str = ""` (or `TAVILY_API_KEY`)
- Add `WEB_SEARCH_ENABLED: bool = False` feature flag

#### 4C. Wire into agents

**File:** `src/agents/retrieval.py`
- Conditionally add `web_search` tool when `WEB_SEARCH_ENABLED=True`

**File:** `src/agents/research_synthesizer.py` (from Phase 3)
- Give web search tool for contextual enrichment while writing
